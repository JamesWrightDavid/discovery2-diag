# references/

Evidence and plans behind the public docs: sniffed protocol detail, reference-tool menus,
the car-test backlog and research notes. Curated facts live in `docs/`, and these files
link there instead of repeating them. The dashboard's Documents tab serves both folders.

## Files

- `test_plan.md` (open tests) and `test-plan-resolved.md` — **the** car-test backlog.
- `protocol_state_handoff.md` — proven, candidate or open per module.
- `slabs/` — SLABS sniff evidence (overview, init timing, services and LIDs).
- `menus/` — reference-tool menu transcriptions, one file per module.
- `reference_tool_menu_map.md`, `*_capabilities.md`, `*_fault_codes.md` — tool and
  vendor references.
- `nanocom_capture_protocol.md` — the NanoCom sniffing-session runbook (T-25).
- `bcu_security_research.md` — the offline BCU seed→key path (ADR-0007).
- `td5-d2-ecosystem.md` — map of every external project, tool and doc; `td5-cross-reference.md`
  — per-LID comparison against them.
- `*_sniff_plan.md`, `*_checklist.md`, `final_session_plan.md`, `car-test-slabs-bcu.md`
  — step-by-step appendices to the test plan.
- `td5-*.md`, `portability-other-vehicles.md`, `input_mapper_design.md` — research.
- `protocol_library.json` — generated by `tools/build_protocol_library.py`.
- `muki01_OBD2_K-line_Reader/` — vendored third-party reference (not indexed).

## Editing rules

- Route every car result here or to the signal store in the same commit as the code.
- Raw logs stay in the gitignored `logs/` and `captures/`. Commit derived facts only.
- Keep files under ~300 lines. Split along headings, not by line count.
- Frontmatter is required. Rebuild INDEX.md after edits.
