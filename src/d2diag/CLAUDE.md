# src/d2diag/

The Ostler pack for Land Rover Discovery 2: the `d2diag` import package. The platform
(`openostler`, https://github.com/openostler/ostler) reaches it only through `PACK`
(entry point `openostler.vehicle` → `lr_d2` → `d2diag:PACK`). The map is in
`docs/architecture.md`.

## Files

- `__init__.py` — assembles `PACK` lazily (module `__getattr__`); importing a module layer
  never builds the pack or pulls in the platform's web layer.
- `td5/`, `slabs/`, `bcu/`, `airbag/`, `ace/`, `autobox/` — the module layers (decoders,
  sessions, keygens, fault maps, menus).
- `signals/*.json` — the single source of truth for LID mappings. Write it only via
  `openostler.signals.upsert_field`; a record may carry `length`.
- `dtc/*.json` — the fault-meaning store. `td5/faultmap.json`, `slabs/faultmap.json` are
  generated by `tools/gen_faultmap.py`.
- `actions.py` (command registry entries), `menus.py`, `catalog_data.py` (`UNLINKED_OK`),
  `faultscan.py` (fault readers), `sniff_spec.py` (address maps, detectors, importers).
- `sources.py` — Td5/SLABS data sources and the fuel computer. The one pack file that
  imports `openostler.web`.
- `sniff/` — NanoCom capture importer, fault-screen importer, emulator map, protocol library.
- `synth.py` + `demo/` — the synthetic demo sessions (regenerate with
  `tools/make_demo_session.py`) and the sniff demo log.
- `layout.json` — the UI layout manifest served by the platform at `/pack`.

## Editing rules

- Platform code (comms core, server, logbook, UI) lives in the platform repo. Import it as
  `openostler.*`; never copy it here.
- Keep `PACK` lazy: building it must not import a module that reads a store at import time.
- Obey the protocol rules in `CONSTITUTION.md` (release(), SLABS polling, tolerant).
- Every change comes with a hardware-free test using `tests/fakes.py`.
